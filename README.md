# Love Minnie Pictures 🌻

## 📖 给徐老师的使用指南 (User Manual)

亲爱的徐老师，您的**“星空下的向日葵画廊”**已经搭建好啦！
这里是为您准备的最简操作手册，只需 3 步，即可让爱的画作上线。

---

### 第一步：准备画作 🎨

1.  画好今天的画（电子版）。
2.  将图片文件改名为今天的日期，格式如下：
    - `20251206.jpg` (年月日) 或 `2025-12-06.png`
    - 推荐使用 `YYYYMMDD` 格式，不仅好记，电脑排序也方便。

### 第二步：生成发布包 📦

1.  双击打开 **`📸_上传图片(admin).html`**。
2.  选择日期、上传图片、填写悄悄话。
3.  点击 **"生成发布包"** 按钮，浏览器会自动下载一个 ZIP 文件到你的下载文件夹。
    - _正言注：页面会自动将图片压缩为 WebP 格式，体积小、加载快！_

### 第三步：一键发布 🚀

1.  双击运行项目里的 **`🚀_一键发布.command`** 脚本。
2.  脚本会自动解压 ZIP、提交到 GitHub、推送到网站。
3.  等待 1-2 分钟，刷新网站，Minnie 就能看到啦！

---

## ✨ 特色功能说明

- **📅 时光画廊**：
  - **今天之前的日子**：显示您画的精美画作。
  - **未来的日子**：显示为一颗未发芽的**向日葵种子** 🌱，点击会提示“由爱灌溉中”。
- **🎟️ 爱的展票**：
  - 点开任意一幅画，会弹出大图。
  - 点击底部的 **“保存为图片 (Save Ticket)”** 按钮，会生成一张像博物馆门票一样的精美卡片，发给 Minnie 更有仪式感！
- **🎵 燕姿时光机**：
  - 点击右下角的**黑色唱片机**，它会开始旋转并播放音乐（需放入 MP3 文件）。

---

## 🔧 技术备注 (Technical Notes)

- **数据**：所有信息存储在 `data.json`，无需数据库。
- **图片**：原图存 `raw_images` (不上传)，网页图存 `images` (WebP 格式)。
- **依赖**：需要安装 Python 和 Pillow 库 (`pip install Pillow`)。

## 2026-04-02 一键发布脚本复盘

这次问题的核心，不在图片包，也不在 GitHub 账号，而在“发送出口”被脚本写死了。脚本默认认定本机代理永远跑在 `33210`，这在代理软件切换、端口变更、或直接网络已可用的情况下，都会把原本能发出的内容拦死在本地。

这次调整后的思路更稳：先尝试直连，失败后再寻找本机真实可用的代理端口，而不是预设一个固定答案。这背后的意义，是把“碰运气式发送”改成“按现场环境判断再发送”，减少同一份发布包反复点击、反复失败的情况。

潜在风险仍然存在于两类情况：一类是 GitHub 本身网络波动，另一类是本机代理开着但规则异常。后续如果还要继续提高稳定性，可以考虑把发布结果单独写入本地日志文件，方便日后直接回看失败原因，而不是只看终端窗口里的瞬时提示。

## 2026-04-08 一键发布脚本权限复盘

这次终端弹窗的根因比较简单：发布文件本身没有坏，真正的问题是 macOS 没有把它当成“可以运行的文件”。所以双击后，系统还没来得及执行发布流程，就直接拒绝了。

这类问题容易误判成脚本坏了、GitHub 坏了、或者 iTerm 设置坏了。更准确的判断方式是看终端里最关键的一行：如果出现 `permission denied`，优先检查文件权限；如果出现 GitHub 或代理相关提示，再去检查网络和代理。

后续如果 Google Drive 同步、文件复制、重新下载导致权限再次丢失，处理方式仍然是恢复 `🚀_一键发布.command` 的可运行权限。今天已经验证脚本语法正常，下载目录里也有当天的发布包，重新双击运行即可继续发布。
