# Love Minnie Pictures 🌻

送给熊老婆的每日画信：打开时看到今天的画与话，也能随时重温过去。

项目完成的标准是画作、日期和文案准确，浏览顺畅，日更能稳定发布并核验。保留首页、今日画信、历史画廊、影院模式、四季主题和 6000 天纪念页。

## 日常上画

把图片和文案交给 AI，并明确说“上传今天这张”。无需改文件名、生成 ZIP 或手动覆盖数据。

统一使用 [love-minnie-daily-upload](/Users/surfin/.agent/skills/love-minnie-daily-upload/SKILL.md)。该入口负责：

1. 检查图片、日期、现有条目和仓库状态，先做 dry-run。
2. 转成 WebP，同步数据，并更新画廊的数据缓存版本。
3. 只提交本次相关文件，推送后核验线上数据与图片。

“今天”取 Asia/Shanghai 当前日期，省略日期参数；“明天发／留到某日”进入候选排期，到期再发布。日期冲突、未来日期和久远回填按现有规则核对，不跳过检查。

旧的网页打包、ZIP 双击发布和批量导入工具已退役，避免多条路径各自维护数据和日期规则。上画流程以这个 Skill 及其脚本为准。

## 数据与文件

| 文件 | 用途 |
| --- | --- |
| `data.json` | 画廊数据源，按日期降序保存 |
| `data.js`、`js/data.js` | 发布脚本生成的兼容数据文件，随数据源同步；不要独立编辑或删除 |
| `images/` | 已发布画作及画廊图标 |
| `index.html` | 首页与纪念日存档入口 |
| `gallery.html`、`js/script.js`、`css/style.css` | 今日画信、历史浏览、日历、影院模式和主题切换 |
| `js/day-6000.js`、`css/day-6000.css` | 6000 天纪念页 |
| `js/anniversary-effects.js` | 纪念日触发与效果 |
| `candidates/` | 候选画与排期素材 |

网站保持原生 HTML/CSS/JS，无框架、数据库或构建步骤。GitHub Pages 与 Zeabur 跟随仓库发布。

## 本地预览与维护

在主项目目录的 `main` 分支工作，不开 worktree。编辑前先查看 `git status`；保留他人和已有修改，只处理本次范围。

```bash
python3 -m http.server 5177 --bind 127.0.0.1
```

- 首页：<http://127.0.0.1:5177/>
- 画廊：<http://127.0.0.1:5177/gallery.html>
- 6000 天完整预览：<http://127.0.0.1:5177/?d6k=1&d6kDev=1>
- 分阶段预览：使用 `?d6k=stage1`、`?d6k=stage2` 或 `?d6k=stage3`。

画作日更按 Skill 完成数据与线上图片核验即可。修改页面后，检查桌面和手机布局，以及受影响的导航、画作详情、日历或纪念页交互。

资源改动时，更新引用它的 HTML 中对应的 `?v=`。修改 day-6000 的 JS 或 CSS 时，同步更新首页与画廊中的纪念页资源版本。不要用全局替换刷新所有版本。

Google Drive 文件读取超时时，先确认文件已下载到本地，再继续；不要把读取失败当成空数据覆盖。

本地修改、提交、推送和线上生效是不同状态。发布须有当前任务授权；使用明确的文件清单暂存并核对差异，不使用 `git add .`。推送后检查实际页面及相关资源，再报告上线。
