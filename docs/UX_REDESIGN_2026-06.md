# 🌹 体验升级方案:把档案馆变回情书

> 2026-06-12 正言。基于全站实测(桌面 1600px + 移动 375px 双端截图走查 + 代码审读)提出。
> 状态:**待徐老师确认**,确认后拆任务进 task_plan.md。

## 核心诊断

这个网站只有一位真正的用户:熊老婆。她每天打开它,想知道的只有一件事:"今天他给我画了什么、说了什么"。

但现在的信息架构是**创作者视角的档案馆**:月份导航、日历打卡、Day 6029 · No. 168 这样的编号。这些是徐老师管理 168 张作品的心智模型。Minnie 不关心 No. 168,她关心那句"今日份爱你"。而这句话目前埋在详情弹窗里,画廊网格、悬停信息、移动端首屏都看不到它。

所以本方案的主线只有一句话:**让"今天的画 + 今天的话"成为每次打开的第一眼,档案能力退居第二层。**

## P0 止血(可用性 bug,改动小,建议本周内)

### P0-1 移动端画廊首屏被日历盖住 🔥
`gallery.html:85` 的 `<aside id="calendar-sidebar" class="calendar-sidebar open">` 硬编码 `open`。桌面端 sidebar 常驻无妨,移动端它变成 bottom sheet,fresh load 直接展开,把画作盖掉 2/3 屏。Minnie 打开画廊第一眼看到的是 SUN MON TUE,不是画。
**改法**:JS 初始化时若 `matchMedia('(max-width: 600px)')` 命中则移除 `open`,或 CSS 在移动端忽略初始 open 态。

### P0-2 Moments 页标题与导航重叠
桌面端 `.page-title`("Moments 点滴·2026")与 `.desktop-nav` 的 HOME 重叠成"点滴·2026OME"。findings.md 里 2026-01-13 的"导航防撞指南"在这个页面没落实。
**改法**:沿用绝对定位解耦方案,title 居中、nav 右侧预留宽度;或移动端才显示 page-title(桌面端隐藏)。

### P0-3 admin 入口暴露给观众
详情弹窗右上角的编辑笔图标、桌面右下角的齿轮,对 Minnie 是噪音,还可能误触。
**改法**:默认隐藏,URL 带 `?admin=1` 才显示。

### P0-4 day-6000 资源版本号不一致
index.html 用 `?v=11.9`,gallery.html / moments.html 还是 `?v=10.4`。跨页打开 6000 天存档时可能命中旧缓存,行为不一致。
**改法**:三处统一到当前最新号,以后 bump 时三个文件一起改(可写进 daily-upload skill 的检查项)。

### P0-5 移动端首页没有任何导航
`.desktop-main-nav` 在 768px 以下直接 display:none,首页只剩 Unwrap 按钮一个出口,Moments 从首页不可达。
**改法**:移动端首页底部加一行极简文字链接(画廊 · 点滴 · 6000 Days),不需要汉堡菜单。

## P1 核心体验:今日情书优先(本方案的灵魂)

### P1-1 画廊页顶部新增"今日卡"Hero 区 ⭐ 最重要的一个改动
进入画廊,第一屏先呈现今天:大尺寸画作 + 中文日期("6月12日 · 在一起的第 6029 天")+ 完整的一句"♥️ 今日份爱你 2026 世界杯来啦"(霞鹜文楷,信纸质感)。往下滚动才进入历史瀑布流。移动端尤其关键,桌面端可做成左图右信的横向 Hero。
这个改动让产品从"图库"变回"每日情书",打开即收信。技术上只是把 data 第一条(今天)抽出来单独渲染,瀑布流从第二条开始,改动集中在 script.js 渲染层 + 一段新 CSS。

### P1-2 影院模式改成"信笺式"排版
现状:桌面右栏只有顶部一小段字,下方大片空白;移动端文字直接压在画面上,无底衬,长文案还会被底部导航裁切。
**改法**:右栏重排为一封信:顶部中文日期与天数,中间情话主体居中、字号放大、手写体,底部固定落款"love, 浩"或"❤"。栏背景加一层极淡的暖色信纸渐变。移动端把文案区放到图片下方的独立面板,带毛玻璃底衬,绝不压画、绝不被导航裁切。

### P1-3 卡片信息层从编号改为情话
hover 现在显示"Day 6029 · No. 168"。改为日期 + 情话前段("6月12日 · 今日份爱你…"),编号信息移到详情页角落小字(徐老师自己看的存档号)。瀑布流图不加常驻文字,保持画面干净,信息只在 hover / 长按浮层出现。

### P1-4 首页加中文情感层
现状首页从标题到按钮全英文,6029 这个最有分量的数字没有任何解释。保留 VISUAL LETTERS 的杂志气质做装饰层,但在数字附近加一行中文:"这是我们在一起的第 6029 天",按钮文案改为"打开第 6029 天"(可保留小字 UNWRAP)。英文负责气质,中文负责击中。

### P1-5 桌面端日历侧栏下半部分利用
380px 宽侧栏日历只占上半,下面长期空白。加两个轻模块:本月小结("六月,已收到 11 封画信")和"随机重温"按钮(随机打开一张旧画详情)。后者给 Minnie 回访的惊喜感,也是最便宜的"再看一眼"入口。

## P2 品牌一致性与精致度

### P2-1 季节主题色调家族化 🎨
四季自动切换是好巧思,但夏季的暗橄榄绿和"星空玫瑰"品牌割裂:绿底配粉色 logo 光晕显脏,一年有大半时间品牌色不在线。
**改法**:保留四季概念,统一以紫夜为基底,季节只换"强调色 + 光晕色":春 = 玫瑰粉(现状),夏 = 萤火虫金绿(深紫夜空 + 暖绿光晕,意象是夏夜萤火),秋 = 琥珀金,冬 = 星霜蓝(现状方向对,可微调)。意象统一成"星空下的花园,四季开不同的花"。具体色值我来调,逐主题给徐老师过目。

### P2-2 首页排版微调
6029 大数字与 LETTERS 标题重叠区域杂乱,描边数字与字母笔画互相打架。把数字下移让出标题底线,或给数字加从上到下的透明度渐变(上淡下实),保持层次而不抢戏。右上角 Est. 2026 / 6000 Days / 导航三组元素做一次对齐与间距规整。

### P2-3 影院模式胶卷条可读性
底部缩略图的数字角标含义不明,当前项不突出。缩略图下加"6.12"式日期角标,当前项加品牌色描边 + 小心形标记。

### P2-4 首页甩掉 Tailwind CDN
index.html 引整包 Tailwind CDN 只用了十几个工具类,是首屏最大的外部负担,也和其他两页(纯手写 CSS)技术路线不一致。改成等价手写 CSS,顺手把首屏字体加载收敛(Google Fonts 已有 preconnect,保持)。

### P2-5 微动效打磨
瀑布流卡片进入视口时做 60ms 间隔的 stagger 渐显;今日卡加极缓的呼吸光晕(同 6000 天那颗"今天"的星的语言);详情打开从卡片位置做 FLIP 过渡取代普通淡入。全部走 transform/opacity,并尊重 prefers-reduced-motion(这条同时覆盖 task_plan 里 A7 的欠账)。

## P3 内容填充(需要徐老师供料)

### P3-1 Moments 数据破零
